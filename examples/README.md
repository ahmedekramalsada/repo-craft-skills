# Example: what a project gets (illustrative only)

These files are **not** generated by running this skills repository. When you load a skill in an actual repository, the coding agent reads that repository and produces a tailored result.

```
my-saas-app/
├── README.md                      # existing onboarding, updated if needed
├── AGENTS.md                      # concise repository-wide agent conventions
├── docs/
│   ├── INDEX.md                   # optional navigation index
│   ├── architecture.md            # optional, real boundaries and flows
│   └── code-map.md                # optional, feature → real source files
└── .agents/skills/
    └── project-maintainer/
        └── SKILL.md               # recurring workflow for THIS project
```

Tiny repositories may only need `README.md`, `AGENTS.md`, and a minimal project-specific skill; unnecessary docs should not be created. Neither `project-map` nor `project-master` may rewrite application logic. `project-refactor` handles code changes separately with verification gates.
